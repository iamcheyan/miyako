# PRD: NAS Music Sync - Android 离线音乐播放器

## Introduction

开发一款 Android 音乐应用，核心功能是将家庭 NAS 上的音乐通过 SMB 协议同步到手机本地，实现离线播放。应用不依赖在线服务，完全基于本地文件夹结构浏览和管理音乐。

## Goals

- 支持 SMBv2/v3 协议连接 NAS 设备
- 保持原始文件夹结构浏览音乐
- 增量同步：仅下载新增/变更文件
- 稳定的离线播放体验
- 支持锁屏/通知栏控制
- 本地记录播放历史和进度

## 技术栈

| 层级 | 技术选择 |
|------|----------|
| 前端框架 | React 18 + TypeScript |
| 构建工具 | Vite |
| 桌面/移动框架 | Tauri 2.0 |
| SMB 客户端 | `smb-client` (Rust crate) |
| 音频播放 | HTML5 Audio API |
| 媒体控制 | MediaSession API |
| 本地存储 | Tauri-plugin-store / JSON 文件 |
| 音频格式 | MP3, FLAC, AAC, WAV |

### US-002: SMB 客户端 Rust 后端
**描述：** 作为开发者，我需要在 Tauri Rust 后端实现 SMB 连接功能，供前端调用。

**验收标准：**

- [ ] 实现 Tauri command `smb_list_dir(connection_id, path)` 返回目录列表

- [ ] 实现 Tauri command `smb_disconnect(connection_id)` 断开连接
- [ ] 实现 Tauri command `smb_get_file_info(connection_id, path)` 获取文件大小和修改时间
- [ ] 错误处理：连接失败、认证失败、路径不存在等场景返回明确错误信息
- [ ] Rust 代码通过 `cargo check` 无错误

**验证方法：** 编写简单的 Rust 测试，或通过前端临时 UI 调用 command 验证连接和目录列表。

### US-005: 同步引擎核心逻辑
**描述：** 作为开发者，我需要实现同步引擎，支持增量扫描和下载。

**验收标准：**
- [ ] 实现 `scan_remote_directory(path)` - 递归扫描远程目录，返回所有音乐文件列表（路径、大小、修改时间）
- [ ] 实现 `compare_with_local(remote_list, local_dir)` - 对比远程和本地文件，返回需要下载的文件列表
- [ ] 比较逻辑：本地不存在 → 需下载；本地文件大小不同 → 需下载；本地文件修改时间早于远程 → 需下载
- [ ] 实现 `sync_download(file_list, local_dir, callback)` - 逐个下载文件，通过 callback 报告进度
- [ ] 下载过程中记录已下载文件，支持断点续传（跳过已下载完成的文件）
- [ ] 同步状态保存到本地：`{ last_sync_time, synced_files: [{remote_path, local_path, size, checksum}] }`
- [ ] Rust 单元测试覆盖核心比较逻辑

**验证方法：** 准备一个测试目录（含新增、修改、未变文件），运行同步逻辑，验证仅下载了需要的文件。

## Functional Requirements

- FR-1: 应用支持 SMBv2 协议连接 NAS，可选 SMBv3
- FR-2: 保存 SMB 连接配置到本地，启动时自动加载
- FR-3: 连接测试功能，返回成功/失败及具体错误信息
- FR-4: 递归浏览远程目录，仅显示音乐文件（.mp3, .flac, .aac, .wav）
- FR-5: 增量同步：基于文件大小和修改时间判断是否需要下载
- FR-6: 同步进度实时显示：进度条 + 文件列表 + 日志
- FR-7: 支持断点续传：中断后重新同步跳过已完成文件
- FR-8: 保持原始目录结构存储本地文件
- FR-9: 离线播放：无需网络即可播放已同步音乐
- FR-10: 播放控制：播放、暂停、上一首、下一首、进度拖动
- FR-11: 播放模式：顺序播放、单曲循环、随机播放
- FR-12: MediaSession 集成：锁屏控制、通知栏控制
- FR-13: 音频焦点管理：其他应用播放时暂停
- FR-14: 播放历史记录：最近播放、完整历史
- FR-15: 播放位置记忆：应用重启后可继续播放
- FR-16: 底部导航：设置、同步、音乐库页面切换

## Non-Goals (Out of Scope)

- ❌ 在线流媒体播放
- ❌ 在线元数据/封面/歌词获取
- ❌ 音乐推荐功能
- ❌ 歌词显示（LRC 文件解析可作为未来功能）
- ❌ 多设备同步
- ❌ 播放列表管理（用户自定义歌单）
- ❌ 均衡器/音效
- ❌ 蓝牙控制（由系统处理）
- ❌ Android Auto 支持
- ❌ 后台定时停止播放
- ❌ 跨文件夹播放（一次只播放一个文件夹内的歌曲）

## Design Considerations

- UI 风格：Material Design 3 简洁风格
- 主色调：深色主题优先（音乐应用场景）
- 布局：底部导航 + 全屏播放器
- 交互：最少点击次数完成核心操作
- 加载状态：所有异步操作显示 loading
- 空状态：每个页面都有空状态提示和引导

## Technical Considerations

- Tauri 2.0 支持 Android，但 SMB 库选择需要验证兼容性
- HTML5 Audio 在 Android WebView 中的行为可能与浏览器不同
- MediaSession API 在 Android WebView 中需要额外配置
- 大量文件同步时需要考虑内存和性能
- Android 权限：需要存储权限、网络权限
- Tauri asset 协议用于加载本地文件到 WebView

## Success Metrics

- SMB 连接成功率 > 95%（常见 NAS 设备）
- 同步 1000 个文件（总计 5GB）时间 < 10 分钟（局域网）
- 增量同步扫描时间 < 5 秒（1000 个文件）
- 应用启动到可播放时间 < 3 秒
- 播放中断率 < 1%
- 应用包体积 < 50MB

## Open Questions

- Tauri 2.0 Android 对 MediaSession 的支持程度如何？是否需要原生插件？
- SMB 连接在 Android WebView 中的长连接稳定性？
- 不同 Android 版本对后台播放的限制如何处理？
- 是否需要支持 SMB 签名（Security Signature）？
